# silkreel CAD v0.2.0-cad.1

Windows x64 预发布版：从真实 KiCad/STEP 模型生成装配图、GLB、交互查看器和制造装配影片。

## 本版重点

- `cad:doctor` 统一检查 Node、KiCad、`pcbnew`、标准模型库、用户 3rdparty、OpenCascade、Chrome、FFmpeg 和 JLC3D，并输出可直接执行的修复命令。
- `cad:bootstrap` 自动安装 npm 依赖、OpenCascade/Pillow 与缺少的 Chromium；KiCad 缺失时明确停止并要求先安装 KiCad 10。
- `repair-models` 和默认自动补模：从 PCB 封装读取 `Value`、`MPN`、`Manufacturer Part`、`LCSC`、`Supplier Footprint` 等字段，按精确型号查询 JLC。
- 已声明但路径失效的模型自动生成项目级 `model-map.json`；完全未声明模型的电气封装自动写入项目内 PCB 副本。
- 使用 JLC `3D Model Transform` 与实测 STEP 包围盒计算 offset/scale/rotate；变换或封装无法唯一确定时停止，不猜。
- JLC 请求支持代理、重试、元数据/STEP 持久缓存；模型 URL、SHA-256、放置变换和“嘉立创EDA/EasyEDA官方库”署名写入 `model-repair.json`。
- 原始 PCB、符号库 `.kicad_sym`、共享 `.pretty` 封装库均不修改。
- 未传 `--out` 时，图片、GLB、查看器、视频、审计、逐帧报告和补模文件统一写入 PCB 同目录的 `<板名>-silkreel/`。

## 兼容范围

完整制造影片仍限普通 4/6 铜层、明确叠层和贯穿孔。2 层、8 层以上、HDI、盲埋孔、刚柔结合等未验证情况会停止，不冒充支持。渲染仍要求 Windows x64、KiCad 10、Chromium、OpenCascade 和 FFmpeg。

下载和安装依赖需要网络。JLC 是第三方在线服务，接口可能变化；缓存可支持已验证模型离线复用，但新器件仍需网络或用户提供精确原厂模型。发布包不包含用户 PCB、下载的第三方模型、项目视频或本机路径。

详细兼容矩阵、Agent 检查项、逐帧验收和故障处理见包内 `README.md`、`AGENTS.md` 与 `packages/cad/README.md`。

## 发布前验收

- `cad:doctor` 在本机确认 KiCad 10.0.6、`pcbnew`、OpenCascade 7.9.3.1.1、Chrome、FFmpeg、KiCad 标准模型库与 JLC3D 路径。
- `cad:bootstrap` 在源码目录和全新解压包中分别创建独立 `.venv-cad`，安装固定版本 OpenCascade/Pillow，并完成最终环境检查。
- 合成回归同时包含路径失效模型、完全未声明模型和纯机械孔：JLC 精确补入 3 个模型，自动生成 `model-map.json`、项目内 PCB 副本和 `model-repair.json`；机械孔正确跳过，原始 PCB、符号库与共享封装库未修改。
- JLC 下载的旋转 0603 模型和 LQFP-48 模型均完成 STEP 面/三角面检查；普通装配渲染生成图片、GLB、查看器与视频。
- 4 层制造入口从原始缺模板完成自动补模、原生 STEP 导出、制造图形提取和静态输出；导出装配缺件清单为空。
- 无准确 MPN/LCSC 的电气封装会停止并给出报文；已验证 JLC 缓存可在断网代理配置下复用。
- 全新解压包可独立完成 `npm ci`、`cad:doctor`、`cad:bootstrap`、JLC 自动补模和 2 秒 20 帧视频回归。
- CAD 类型检查、ESLint 和原生测试 17 项通过；全仓库为 348 通过、15 个上游 Windows 环境测试失败（macOS 固定 FFmpeg 路径、路径分隔符和符号链接权限），未标记为全仓库全绿。
